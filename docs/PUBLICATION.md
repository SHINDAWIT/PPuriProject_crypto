# 공개 범위와 자료 출처

[처음으로](../README.md)

## 공개한 자료

- 프로젝트 목적·구조·환경 변경 대응·개인 역할을 정리한 설명
- C 공개 인터페이스와 최소 Node·Java 어댑터 6개
- 새로 작성한 호출 예제와 공개 코드 검사
- 기존 배포물의 시험 문서·빌드 정보 중 기술적 결과를 선별한 요약
- 사용자가 제공한 업무 메일의 익명화된 요구사항·전달 이력

## 공개하지 않은 자료

- ARIA·해시·HMAC 등의 native 암호 구현 소스와 전체 원본 Git 이력
- 업체 전달용 바이너리·소스 압축파일, 실제 키·인증정보·운영 설정
- 메일 원문·원본 첨부물·서명·연락처·상대 담당자·회사와 수요 업체 이름
- RTU·데이터맵·원본 Flow·실제 메시지·내부 접속 정보
- 내부 개발도구의 프롬프트·대화 로그와 연구노트 원문

원 프로젝트는 암호 구현을 바이너리로 전달하는 경계를 두었다. 이 포트폴리오는 그 구현 소스를 공개하는 경로로 사용하지 않는다. 공개 코드에 전체 프로젝트나 제3자 자료를 포괄하는 새로운 오픈소스 라이선스를 붙이지 않았다.

## 근거와 귀속

| 자료 | 근거의 성격 |
|---|---|
| 기존 소스·Git 변경 | 구현·수정 파일의 존재. 커밋 계정만으로 개인 수작업 기여를 확정하지 않음 |
| 당시 개발도구 요청 프리뷰 | 환경 정보 전달·요구·검토·수정·시험 요청 활동. 원문 전체가 보존된 것은 아님 |
| 기존 배포물의 빌드·시험 문서 | 해당 후보에 기록된 환경·revision·PASS 요약. 원시 실행 로그 독립 검증과 구분 |
| 사용자 제공 업무 메일 | 적용 구간·런타임 회신, 협력사 Bridge 제안, 모듈 전달·수령. 원본 헤더·첨부파일 검증과 구분 |
| 이번 공개 저장소의 예제·검사 | 포트폴리오 설명·검토를 위해 AI 개발도구로 작성. 과거 프로젝트 산출물과 구분 |

실제 전체 참여 기간, 동료의 세부 분담·기여율, 고객 적용·수용 완료는 확정하지 않았다. 소속은 사용자가 제공한 본인 메일의 부산대학교 석사과정·연구실 설명을 반영했다.

## 공개 전 점검

허용 목록에 있는 파일만 새 Git 이력으로 올린다. 코드·문서·JSON의 기본 민감 패턴과 링크를 검사하고, 원문에 등장한 개인정보·업체 식별자가 공개 파일에 들어 있지 않은지도 별도로 대조한다. 자동 검사만으로 모든 비밀·권리 문제를 보장하는 것으로 표현하지 않는다.

공개 자료 목록은 [public_files.json](../evidence/public_files.json), 기존 파일 출처는 [source_manifest.json](../evidence/source_manifest.json), 공개 검사 기록은 [portfolio_checks.json](../evidence/portfolio_checks.json)에서 확인할 수 있다.

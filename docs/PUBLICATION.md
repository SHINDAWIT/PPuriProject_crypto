# 공개 범위와 자료 출처

[처음으로](../README.md)

## 공개한 자료

- 프로젝트 목적·구조·환경 변경 대응·개인 역할을 정리한 설명
- C 공개 인터페이스와 최소 Node·Java 어댑터 6개
- 새로 작성한 호출 예제와 공개 코드 검사
- 기존 배포물의 시험 문서·빌드 정보 중 기술적 결과를 선별한 요약
- 협력사 업무 메일을 바탕으로 정리한 요구사항·전달 이력

## 공개하지 않은 자료

- ARIA·해시·HMAC 등의 native 암호 구현 소스와 전체 원본 Git 이력
- 업체 전달용 바이너리·소스 압축파일, 실제 키·인증정보·운영 설정
- 메일 원문·원본 첨부물·서명·연락처·상대 담당자·회사와 수요 업체 이름
- RTU·데이터맵·원본 Flow·실제 메시지·내부 접속 정보
- 내부 개발도구의 프롬프트·대화 로그와 연구노트 원문

암호 구현은 바이너리로 전달하는 방식이며, 이 저장소에는 인터페이스와 어댑터만 공개했다. 전체 프로젝트와 제3자 자료에 적용되는 별도의 오픈소스 라이선스는 부여하지 않았다.

## 자료 구성

| 자료 | 내용 |
|---|---|
| 프로젝트 소스 | C 인터페이스와 Node·Java 어댑터. 파일별 원본 경로·해시 기록 |
| 배포 패키지의 빌드·시험 문서 | 실행환경·revision 및 패키징 템플릿으로 생성된 시험 요약 |
| 협력사 업무 메일 요약 | 적용 구간·런타임 협의, Bridge 제안, 모듈 전달·수령 |
| 공개 저장소의 예제·검사 | AI 개발도구로 작성한 API 호출 예제와 계약·컴파일 검사 |

프로젝트의 코드 작성·수정·시험·패키징에는 AI 개발도구를 활용했다. 공개 예제·검사는 기존 전달 패키지와 별도로 작성했다.

## 공개 전 점검

선별한 파일 목록을 기준으로 코드·문서·JSON의 개인정보·내부 경로·인증정보 패턴과 내부 링크를 검사한다. 업체 식별자와 원본 메일·첨부물은 공개 대상에서 제외한다.

공개 자료 목록은 [public_files.json](../evidence/public_files.json), 기존 파일 출처는 [source_manifest.json](../evidence/source_manifest.json), 공개 검사 기록은 [portfolio_checks.json](../evidence/portfolio_checks.json)에서 확인할 수 있다.

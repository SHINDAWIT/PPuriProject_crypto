# 협력사와의 요구사항 확인·전달 이력

[처음으로](../README.md) · [개발 사례](CASE_STUDY.md)

## 협의 개요

협력사와 암호 적용 구간, 실행환경, 호출 방식과 전달 패키지를 메일로 협의했다. 아래는 협의 순서에 따른 기술 내용 요약이며, 업체명·담당자·연락처와 실제 데이터는 제외했다.

## 주요 확인 과정

| 순서 | 주체와 확인 내용 | 정리된 요구·결과 |
|---|---|---|
| E01 | 연구실 측: Edge→Kafka 구간과 Gateway→Client 구간의 암호 적용 범위 질의 | 적용 구간, 대상 데이터, Node-RED 모듈과 가이드의 제공 범위 확인 요청 |
| E02 | 협력사: Edge 송신·수신 측 복호화 구조와 대상 데이터 범위 회신 | Gateway→Client는 HTTPS를 적용하는 프로젝트 범위로 정리. Node-RED 팔레트 노드와 키 사용 가이드 요구 |
| E03 | 연구실 측: Node·N-API·이미지·Flow·payload 타입과 Consumer 런타임·호출 위치 질의 | 기존 시스템에 맞는 개발 언어·배포 형식·호출 경계를 결정하기 위한 정보 요청 |
| E04 | 협력사: Node 20.18.0·N-API 9·latest 이미지·Spark Java 8 등의 정보 회신 | 별도 Bridge를 통한 복호화 후 기존 topic 재전송을 협력사가 제안 |
| E05 | 연구실 측: latest의 실제 이미지 식별과 Bridge 실행 Java 버전 재질의 | 모듈을 실제 로드하는 환경을 고정하기 위한 추가 확인 |
| E06 | 협력사: 고정 Node-RED 4.0.5 digest 및 시스템별 Java 버전 회신 | Spark Java 21 마이그레이션 완료, Broker Java 8, Bridge Java 21로 구분 |
| E07 | 연구실 측: 개발 모듈 압축파일 전달, 적용·시험 중 문제와 개선 사항 회신 요청 | 모듈 전달 및 후속 피드백 요청 |
| E08 | 협력사: 파일 수령 확인, 적용·시험을 진행하겠다고 회신 | 수령 후 적용·시험 예정 |

## 협의 결과와 남은 연동 항목

- 협력사가 제안한 Bridge 구조에 맞춰 모듈 호출 환경과 언어별 패키지를 준비했다.
- 환경·요구사항 정리, AI 개발도구를 활용한 개발·수정·시험, 전달본·문서 검토와 모듈 전달을 담당했다.
- 협력사는 모듈을 수령하고 적용·시험 계획을 회신했다. 후속 적용·시험 결과는 이 저장소에 포함되어 있지 않다.
- 초기 팔레트 노드 요구와 보관 패키지의 라이브러리·wrapper 구성 차이는 후속 협의 항목이다.

Gateway→Client 구간은 HTTPS를 적용하고, Edge→Kafka 구간은 payload 암호화를 적용하는 범위로 협의했다.
